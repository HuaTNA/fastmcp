FastMCP implements the MCP Skills extension. A `Skill` is an immutable, storage-neutral bundle of instructions and files. Providers publish those bundles as resources, while `SkillsExtension` adds the protocol methods that let clients discover a skill and retrieve its verified content.

## Publish skills

Create a skill in Python when its content belongs in your application, or load a snapshot from one skill directory. Loading a directory reads it once; later disk changes do not alter the `Skill` object.

```python
from fastmcp import FastMCP, Skill
from fastmcp.server.providers.skills import SkillProvider
from fastmcp.server.skills import SkillsExtension

skill = Skill(
    name="refunds",
    description="Help support staff handle refund requests.",
    instructions="Check the order date and payment status before issuing a refund.",
    files={"references/policy.md": "Refunds are available within 30 days."},
)

mcp = FastMCP("Support")
mcp.add_provider(SkillProvider(skill))
mcp.add_extension(SkillsExtension())
```

`Skill.from_directory(path)` constructs the same immutable object from a directory containing `SKILL.md`. The directory name must match the skill's frontmatter `name`. Additional files retain their relative paths and exact bytes.

`SkillProvider` also accepts `path="billing/refunds"` or a full `uri="catalog://billing/refunds/SKILL.md"`. The directory immediately before `SKILL.md` must match the skill's `name`.

For application-owned storage, pass a mapping of relative paths to `Skill.from_files()`, or load packaged assets with `Skill.from_package(package, path)`. These constructors return the same snapshot type, so providers do not need to know whether the source was Python code, a database, a package, or a directory.

Use `SkillCatalogProvider` when the catalog itself belongs to an application service. Its async callbacks return `SkillPublication` values; an optional direct lookup callback avoids listing the full catalog for `skills/get` and resource reads.

FastMCP includes a static skill in `skills/list` or `skills/get` only when every file in its manifest is readable to that client. This keeps the manifest aligned with resource authorization and transforms. A direct catalog lookup can serve a skill through `skills/get` and directory reads even when that skill is absent from the catalog listing.

```python
from fastmcp import FastMCP, Skill
from fastmcp.server.providers.skills import (
    SkillCatalogProvider,
    SkillPublication,
)
from fastmcp.server.skills import SkillsExtension

async def list_from_database() -> list[SkillPublication]:
    record = {
        "SKILL.md": """---
name: refunds
description: Refund support.
---
Check the current billing policy.""",
        "references/policy.md": "Refund policy from the application catalog.",
    }
    skill = Skill.from_files(record)
    return [SkillPublication(skill=skill, path="billing/refunds")]

mcp = FastMCP("Billing")
mcp.add_provider(SkillCatalogProvider(list_from_database))
mcp.add_extension(SkillsExtension())
mcp.run()
```

```python
from pathlib import Path

from fastmcp import FastMCP, Skill
from fastmcp.server.providers.skills import SkillProvider
from fastmcp.server.skills import SkillsExtension

skill = Skill.from_directory(Path("skills/refunds"))
mcp = FastMCP("Support")
mcp.add_provider(SkillProvider(skill))
mcp.add_extension(SkillsExtension())
```

## Load a directory of skills

Use `SkillsDirectoryProvider` to publish every skill below one or more roots. It takes an initial snapshot when constructed. Call `await provider.reload()` to atomically replace that snapshot after files change. `reload=True` enables automatic rescanning for development.

```python
from pathlib import Path

from fastmcp import FastMCP
from fastmcp.server.providers.skills import SkillsDirectoryProvider
from fastmcp.server.skills import SkillsExtension

provider = SkillsDirectoryProvider(Path("skills"))
mcp = FastMCP("Support")
mcp.add_provider(provider)
mcp.add_extension(SkillsExtension())

# After updating the directory:
# await provider.reload()
```

Each skill must live in a directory whose final path segment matches its frontmatter name. Nested directories are allowed. Symlinks, unsafe relative paths, invalid frontmatter, duplicate publication paths, and bundles over the protocol size limits are rejected when a snapshot is built.

## Retrieve skills from a client

FastMCP clients check the server's advertised extension capability, paginate `skills/list`, fetch a skill by URI, and verify downloaded bytes against the manifest's SHA-256 digest and size.

Use `iter_skills()` to process large catalogs a page at a time, or `list_skills()` when the complete catalog fits in memory.

For a terminal overview, run `fastmcp list <server> --skills` or add `--json` for machine-readable output.

```python
import asyncio

from fastmcp import Client

async def main() -> None:
    async with Client("http://localhost:8000/mcp") as client:
        for skill in await client.list_skills():
            print(skill.name, skill.description, skill.origin)
            instructions = await skill.read()
            print(instructions.text)
            policy = await skill.read("references/policy.md")
            print(policy.text)

asyncio.run(main())
```

`RemoteSkill.read()` returns verified bytes, MIME type, resource URI, skill URI, and origin. It rejects files absent from the manifest and content whose size or digest has changed. A skill that declares dynamic resources must be read with `allow_unverified=True`; dynamic content cannot be checked against a static manifest.

The optional `resources/directory/read` method supports directory browsing. The server advertises it as `directoryRead: true`, and `client.read_resource_directory(uri)` follows its pagination. Clients can also call `list_skills_mcp()` and `get_skill_mcp(uri)` when they need the raw protocol result or manual pagination.

When proxying a server that does not support directory reads, FastMCP derives a static skill's tree from its manifest. For a dynamic skill, it uses the upstream resources currently visible in `resources/list`. Empty directories and dynamic files absent from those sources cannot be reconstructed.

## Trust and activation

The extension transports skill content. It does not activate instructions, grant tools, or decide whether a host should trust a skill. Hosts must apply their own review, permission, and execution policies to received content.

The manifest describes the exact bytes the server publishes. Clients should keep the skill's origin attached when caching or presenting content, and should treat the content as untrusted input even after integrity verification: the digest proves consistency with the server's manifest, not that the instructions are safe.
